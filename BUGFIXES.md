# Исправленные баги (ноябрь 2026)

## Бот
- **Ленивые связи в async** (`order.employer`, `response.order/worker`, `worker.user` и др.) падали с MissingGreenlet:
  не приходили уведомления админам о заявках/откликах, ломались «Мои отклики», подтверждение отклика.
  Исправлено: `lazy="selectin"` для связей many-to-one в моделях.
- `notifications.py`: не был импортирован `ResponseStatus` (NameError). Голые `except: pass` заменены на логирование.
- Работник с «Любая работа» (без категорий) не видел вакансий и не получал рассылку. Теперь видит все вакансии своего города.
- Комиссия считалась по-разному в боте и в `OrderService`. Теперь единая функция `calculate_order_cost` в `config/settings.py`;
  в БД пишется та же сумма, что показана работодателю (с учётом почасовой оплаты). `Order.total_cost` тоже учитывает часы.
- Добавлены обработчики команд `/help`, `/profile`, `/support`, `/cancel` (и кнопки «❌ Отмена»). `/cancel` работает посреди любой анкеты.
- Добавлены обработчики кнопок без хендлеров: «📊 Статус заказа», «👥 Отклики», «🗑 Отменить» в «Мои заявки»,
  «💬 Связаться» у админа, «⭐️ Оценить работника» (оценка 1–5 + комментарий, пересчёт рейтинга).
- Новая админ-команда `/complete <номер заявки>`: завершает смену, +1 смена работникам, работодателю приходит запрос оценки
  (раньше `notify_employer_shift_completed` нигде не вызывалась).
- `/admin` считал заявки со статусом MODERATION, а бот создаёт CREATED, счётчик всегда был 0.
- В заявке выбиралась только дата, работники видели «в 00:00». Добавлен шаг выбора времени начала смены.
- Повторная регистрация работодателя после отказа падала на unique(user_id). Теперь анкета обновляется и уходит на проверку.
  Также проверка «уже зарегистрирован» смотрела id бота вместо пользователя.
- Повторная регистрация/двойной клик у работника тоже падали на unique(user_id).
- Если пользователь выбрал роль, но бросил регистрацию, /start теперь продолжает регистрацию, а не показывает пустое меню.
- Повторное нажатие «Одобрить» у админа рассылало вакансию работникам ещё раз; повторный отклик ещё раз уведомлял админов.
- Можно было откликнуться на закрытую/отменённую вакансию; подтвердить больше работников, чем нужно.
  После набора нужного числа заявка уходит в статус «Подтверждение работников».
- Работнику приходит уведомление об отклонении отклика.
- Ввод с `<` или `>` (название компании, описание, адрес) ломал сообщения с HTML-разметкой. Пользовательский текст экранируется.
- Стикер/фото вместо текста в анкете вызывали AttributeError. Сумма с запятой («1500,50») не принималась.
- Профиль длиннее 1024 символов не отправлялся как подпись к фото. Теперь отправляется текстом.
- Захардкоженный путь `C:\Users\tuchk\...` для картинок. Теперь `ASSETS_DIR` из .env, по умолчанию папка `assets` в проекте.
- `Review.is_hidden` был String вместо Boolean.

## Веб-админка
- Не было шаблонов `orders/*.html` и `workers/*.html` (TemplateNotFound). Добавлены.
- `first_or_404()` не существует у обычной SQLAlchemy-сессии: все страницы «Подробнее» падали с 500. Заменено на `get_or_404`.
- `user_loader` был только в `run_admin.py`, под gunicorn вход не работал. Перенесён в `admin/__init__.py`.
- Open redirect через `?next=` при входе. Добавлена CSRF-защита всех POST-форм. Сравнение пароля через `hmac.compare_digest`.
- Одобрение/отклонение в веб-панели не отправляло уведомлений в Telegram. Теперь отправляет (через Bot API), включая рассылку вакансии.
- Дашборд: счётчик «На модерации» учитывает статус CREATED.

## Прочее
- В requirements.txt не было `aiosqlite`, без него бот не запускался на SQLite.
- `.gitignore`: добавлен `*.sqlite`. `.env.example`: добавлены `USE_SQLITE`, `ASSETS_DIR`, убран неиспользуемый `COMMISSION_AMOUNT`.

## Обновление зависимостей (2026-11-27)
- Все пакеты обновлены до актуальных версий с готовыми wheel для Python 3.14 на Windows
  (раньше pip пытался собирать psycopg2-binary, aiohttp, asyncpg, pydantic-core из исходников и падал).
  Основное: aiogram 3.4.1 → 3.34.0, aiohttp 3.9.3 → 3.14.5, SQLAlchemy 2.0.27 → 2.1.9,
  pydantic 2.5 → 2.14.4, asyncpg 0.29 → 0.32, psycopg2-binary 2.9.9 → 2.9.13, Flask 3.0 → 3.1.3.
- SQLAlchemy 2.1 больше не ставит greenlet сам, поэтому в requirements `sqlalchemy[asyncio]`.
- gunicorn ставится только не на Windows (на Windows он не работает; админка запускается через `python run_admin.py`).
- Добавлен `tzdata` (на Windows нет системной базы часовых поясов).
- Код правок под новые API не потребовал. В `run_bot.py` при остановке теперь закрывается пул БД (`engine.dispose()`).
- Новый venv создан на Python 3.14 в папке `venv`; старый (Python 3.12) переименован в `venv_old_py312`, его можно удалить.
